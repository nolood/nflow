## Codebase Patterns
- Workspace root Cargo.toml uses `[workspace.package]` for shared version/edition/rust-version
- Use `workspace = true` in crate Cargo.toml to inherit shared fields
- nflow-core must NEVER have tokio, async, or IO deps — keep it pure logic
- All other crates depend on nflow-core via `{ workspace = true }`
- Empty .rs module files need a trailing newline to pass `cargo fmt --check`
- Binary crates use `[[bin]]` in Cargo.toml with explicit path
- uuid and chrono crates need `serde` feature enabled for Serialize/Deserialize derives
- Use `impl Fn` closures for external checks to keep nflow-core pure (no IO traits)
- NflowError enum in error.rs: Validation, NotFound, Conflict, InvalidState, InvalidTransition, Serialization
- State machines use `&mut self` methods returning `Result<()>` with InvalidTransition errors
- SpecStatus has Display impl for use in error messages
- WorkItemStatus is a unified enum (Pending, Ready, InProgress, Done, Failed, Cancelled) — not all states valid for all item types
- Use `assert_story()` / `assert_task()` guards at the top of type-specific state machine methods
- propagate_epic_status() takes a slice of statuses, not full WorkItems — keeps it simple
- Use `contains()` instead of `iter().any(|s| *s == ...)` for clippy compliance (manual_contains lint)
- Dependency is story-level only — validated by convention, not struct constraints
