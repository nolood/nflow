## Codebase Patterns
- Workspace root Cargo.toml uses `[workspace.package]` for shared version/edition/rust-version
- Use `workspace = true` in crate Cargo.toml to inherit shared fields
- nflow-core must NEVER have tokio, async, or IO deps — keep it pure logic
- All other crates depend on nflow-core via `{ workspace = true }`
- Empty .rs module files need a trailing newline to pass `cargo fmt --check`
- Binary crates use `[[bin]]` in Cargo.toml with explicit path
- uuid and chrono crates need `serde` feature enabled for Serialize/Deserialize derives
- Use `impl Fn` closures for external checks to keep nflow-core pure (no IO traits)
- NflowError enum in error.rs: Validation, NotFound, Conflict, InvalidState, InvalidTransition, Serialization, CyclicDependency
- State machines use `&mut self` methods returning `Result<()>` with InvalidTransition errors
- SpecStatus has Display impl for use in error messages
- WorkItemStatus is a unified enum (Pending, Ready, InProgress, Done, Failed, Cancelled) — not all states valid for all item types
- Use `assert_story()` / `assert_task()` guards at the top of type-specific state machine methods
- propagate_epic_status() takes a slice of statuses, not full WorkItems — keeps it simple
- Use `contains()` instead of `iter().any(|s| *s == ...)` for clippy compliance (manual_contains lint)
- Dependency is story-level only — validated by convention, not struct constraints
- Task state machine: pending→in_progress→done|failed|cancelled; failed→in_progress(retry), failed→done(skip); pending→cancelled
- auto_generate_verify_tasks() works on a slice of WorkItems, filtering for impl tasks only
- skip_task() takes &mut impl_task + &mut [WorkItem] slice for paired verify manipulation
- find_paired_verify/find_paired_impl use parent_id + sort_order±1 matching
- ShortIdGenerator has independent counters for epic/story/task — counters are per-decomposition-session
- ShortIdRegistry maps (wave, short_id) -> UUID; resolve() accepts "W1-S1" or bare "S1" with optional context_wave
- parse_wave_prefixed() and parse_short_id() are pure parsing functions — no registry needed
- assign_short_ids() updates generator counters from existing IDs to avoid collisions
- Dag struct stores forward (blocker→blocked) and reverse (blocked→blockers) adjacency lists as HashMap<Uuid, HashSet<Uuid>>
- build_dag() filters non-story items, validates same-session, validates dep references, checks for cycles
- find_ready_stories/find_blocked_stories treat Cancelled same as Done for unblocking
- detect_cycle() uses DFS with White/Gray/Black coloring; topological_sort() uses Kahn's algorithm
- Sort Uuid collections for deterministic test output (HashSet iteration is non-deterministic)
- Scheduler is a pure function: schedule(&SchedulerState) -> Vec<SchedulerAction> — no mutations, no IO
- SessionStatus enum (InProgress, Approved, Discarded) gates story schedulability — only Approved sessions produce actions
- SchedulerAction enum: MarkStoryReady, StartStory, UpdateEpicStatus — daemon executes these
- Scheduler groups stories by session to build per-session DAGs, then uses find_ready_stories() from dag module
- DecompositionSession uses `impl Fn(Uuid) -> bool` for has_in_progress check (same closure pattern as ProjectService)
- DecompositionStatus is separate from scheduler::SessionStatus — scheduler uses its own lightweight enum
- discard_session() is a free function that orchestrates session.discard() + work item collection + spec freeing
- next_wave_number() takes &[u32] slice of existing wave numbers — pure computation
- Config uses PartialConfig (all-optional) for layered merging: defaults → global toml → per-project toml → env vars
- partial_config_from_env() takes &[(&str, &str)] to keep nflow-core IO-free — caller reads actual env vars
- render_branch_template() supports {project}, {story_id}, {story_slug} variable substitution
- DB schema lives in nflow-daemon (not nflow-core) since it does IO via rusqlite
- Migration files go in `crates/nflow-daemon/migrations/` and are embedded via `include_str!`
- MIGRATIONS const is &[(u32, &str)] — version number paired with SQL string
- Use `unchecked_transaction()` for rusqlite transactions (doesn't require &mut Connection)
- SQLite stores UUIDs as TEXT, booleans as INTEGER (0/1), timestamps as TEXT (ISO 8601)
- Foreign keys need `PRAGMA foreign_keys = ON` on every connection open
- WAL mode set via `PRAGMA journal_mode = WAL` on connection open
- In-memory SQLite uses "memory" journal mode even when WAL is requested — tests should accept both
